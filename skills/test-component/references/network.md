# Faking the network

Fake HTTP at the request boundary so the component's own client, hooks, caching and error
mapping all run. Mock Service Worker (MSW) intercepts `fetch` and `XMLHttpRequest` in Node and,
with a service worker, in the browser; the same handlers serve component tests, Storybook and
local development.

## Setup in Node (jsdom, happy-dom)

```ts
import { http, HttpResponse } from "msw";
import { setupServer } from "msw/node";
import { afterAll, afterEach, beforeAll } from "vitest";

export const server = setupServer(
	http.get("https://api.example.test/invoices", function invoices() {
		return HttpResponse.json({ invoices: [{ id: "INV-1", totalCents: 12000 }] });
	}),
);

beforeAll(function listen() {
	server.listen({ onUnhandledFrame: "error" });
});

afterEach(function reset() {
	server.resetHandlers();
});

afterAll(function close() {
	server.close();
});
```

- **Fail on unhandled requests.** MSW 3.0 names the option `onUnhandledFrame`; MSW 2 named it
  `onUnhandledRequest`. Measured with MSW 3.0.3: with `onUnhandledFrame: "error"` an unhandled
  `fetch` rejects (`TypeError: fetch failed`, cause "Cannot bypass a request when using the
  "error" strategy") and MSW logs the request; the old `onUnhandledRequest: "error"` is
  ignored and the request goes to the real network. Rename it on upgrade, and keep a test that
  proves an unhandled request fails.
- **Default handlers are the happy path.** Put them in one module shared by tests, stories and
  development. Override per test with `server.use(...)`; `resetHandlers` in `afterEach` drops
  the overrides.
- **Use the same base URL the app's client uses.** Under Vitest's jsdom environment
  `location.href` is `http://localhost:3000/`, so relative URLs resolve there.

## Per-test states

```ts
function failInvoices(status: number): void {
	server.use(
		http.get("https://api.example.test/invoices", function failure() {
			return HttpResponse.json({ message: "unavailable" }, { status });
		}),
	);
}
```

Cover each state the screen has: success, empty list, 4xx with a field error, 5xx, network
failure (`HttpResponse.error()`), slow (`await delay(...)` inside the resolver, then assert the
loading state), and a malformed body if the client validates responses.

## Asserting what the component sent

When the request is the behavior (a form submit, a filter, pagination), record it in the
handler and assert method, URL, query and body, and the count (no double submit):

```ts
const received: unknown[] = [];

server.use(
	http.post("https://api.example.test/coupons", async function record({ request }) {
		received.push(await request.json());

		return HttpResponse.json({ ok: true });
	}),
);

// ... act through the UI, wait for the confirmation ...
expect(received).toEqual([{ code: "SAVE10" }]);
```

## What not to mock

- The component's own hooks, data modules or child components (`vi.mock("./useInvoices")`):
  the code under test no longer runs. Measured in this repository: a test that rendered the view
  with a canned error state passed while the real hook rendered the empty state on a 500.
- `fetch` or the HTTP client module replaced with a hand-built object: it rarely has a real
  `status`, `ok`, headers and body, so status handling goes untested.
- Your own API module when MSW can answer the request instead.

Mocking is right for what lives outside the process or the browser model: the network (through
MSW), the clock, randomness, and browser APIs jsdom lacks (`matchMedia`, `IntersectionObserver`,
`ResizeObserver`, `scrollIntoView`, canvas). When the component receives a client through props
or context, an in-memory fake client with named failure modes is as good as MSW.

## Other transports

- GraphQL: `graphql.query("InvoiceList", resolver)` and `graphql.mutation(...)`. In MSW 3.0
  `graphql` is exported from `msw/graphql`, not from `msw`; MSW 2 exported it from `msw`.
- WebSocket and server-sent events: `ws` and `sse` from `msw`; push messages from the test,
  then `findBy` the result.
- Browser-mode runners: `setupWorker` from `msw/browser` with the worker script generated by
  `npx msw init`, started before the first render.
